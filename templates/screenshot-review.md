# SCREENSHOT REVIEW

## Ground rule

Analyze only what is visible in the screenshot. Never invent details that are not shown — no assumed flows, no guessed interactions, no imagined content. If something is cropped or illegible, say so and review around it.

## Inspection sequence

1. **Composition** — visual anchor, balance, alignment edges, reading path
2. **Hierarchy** — what reads first, second, third; is that the right order?
3. **Typography** — type scale, weight contrast, density, alignment, metadata treatment
4. **Spacing** — rhythm, gutters, grouping, spacing consistency
5. **Color** — palette, accent discipline, value contrast, semantic use
6. **Components** — geometry, repetition, state visibility, consistency
7. **Density** — sparse/balanced/dense per region; does density match importance?
8. **Brand** — identity signals; could this screenshot belong to any product?
9. **Decoration** — every decorative element named and justified, or flagged

## Output

1. One-sentence overall diagnosis
2. Top three visible problems, ordered by impact
3. Concrete changes with expected outcome
4. P0–P3 priorities

## Limits

- Note what *cannot* be assessed from a static image: interaction, motion, real responsive behavior, actual contrast ratios (unless measurable from the image), accessibility states.
- Offer the follow-up that would resolve the limit (code review, responsive review, more screenshots at other breakpoints).
